Synthetic video QA from Blender scenes: samples

Each clip below was written as code for one target skill (a node of a skill tree induced from video-QA benchmarks), rendered in Blender, and paired with multiple-choice questions whose answers are read from the saved .blend file, not written by hand. These items come from wave 1 of the dataset (in progress; wave 2 is being written and rendered now).

How an item is made

  1. Brief. A Claude Sonnet agent gets one skill node (name + definition) and writes scene.py with a small Blender API: coloured primitives, text signs and procedural furniture from Infinigen, placed and keyframed; one camera. Render settings are fixed by the harness.
  2. Facts from the file. The agent writes facts.py, which opens the saved .blend, steps through all 24 frames and computes each fact (positions, turns, counts, colours, depth order). The harness re-runs it.
  3. Questions. Each question names the fact it rests on; it is kept only if its keyed answer equals the fact's value.
  4. Render and filter. 24 frames at 480×270 (Cycles, 32 samples), shown to models as a 12-second clip at 2 frames per second. A question is dropped if the objects it asks about are too small, cut off or occluded in the rendered ground-truth maps, and by pooling rules that remove fragile question types (absolute distances, shadow length, brightness at an instant). Options are shuffled.

The videos on this page are exactly what the models see (24 frames, 2 fps). Answers hidden by default.

Samples by skill area

Two scenes per top-level skill area (L2), each from a different skill node, picked from scenes with at least four kept questions and no open review flag. All kept questions of each scene are shown.
