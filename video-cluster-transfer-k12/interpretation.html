What is in each K = 12 cluster? Four readings

The transfer experiment split 63,610 video multiple-choice questions into 12 k-means clusters in two embedding spaces: the skill encoder (gte-modernbert fine-tuned so that questions with the same LLM skill labels sit close together) and the frozen embedder it started from. This page reads the clusters four independent ways, then asks whether the four readings agree.

  1. Skill-label enrichment. Which skill-tree labels are over-represented in the cluster, by coverage (share of the cluster's questions carrying the label) and ratio (coverage ÷ share in all 63,610 questions).
  2. Nearest skill-node names. The skill-tree node names whose embeddings (in the same space) lie closest to the cluster centre. The encoder was trained on these names, so this reads the clusters in the encoder's own terms.
  3. Centroid hierarchy. The 12 centres clustered again (average linkage, cosine distance). Do clusters that merge early share a parent skill?
  4. Language-model reading. A language model saw 40 sample questions per cluster (question and options only; no labels, no benchmark names) and wrote a name and definition, then contrasted each cluster with its nearest neighbour.

The skill tree has two levels here: 26 parent skills (L2) and 335 sub-skills (L3), induced from LLM labels of every question. A question's labels are the union over its requests. No question text from any benchmark is shown on this page.

Overview: the main skill each reading picks

One row per cluster. Each reading is reduced to one parent skill (L2): enrichment's characteristic L2 (largest coverage × log ratio among over-represented L2s); the L2 name nearest the centre; and the L2 name nearest the language model's own name + definition, embedded in the same space. A filled dot means that reading's L2 matches enrichment's.

1. Skill-label enrichment

Over-represented means ratio ≥ 1.5 with coverage ≥ 5 % (L2) or ≥ 3 % (L3). Sub-skills are ranked by coverage × log ratio; bars show coverage, the number on the right is the ratio. The top three benchmarks by share are listed for comparison.

2. Nearest skill-node names

Cosine between the cluster centre and each node, using the mean embedding of the node's four name wordings (three seen in training, one held out). A filled dot marks a sub-skill that is also over-represented in the cluster (reading 1). Node definitions, which the encoder never saw, match less well and are not shown.

3. Centroid hierarchy

Each leaf is a cluster, labelled with its language-model name and, in brackets, its characteristic parent skill. Blue joins merge clusters whose characteristic parent skills match. The Mantel tests compare the distances between centres with distances between the clusters' skill-label profiles and benchmark mixes (20,000 permutations).

The encoder's agreement with the tree is partly by construction: it was trained to place questions with the same labels together.

4. Language-model reading

claude-sonnet-5-5, thinking off. Check: a separate call received only the 12 names and definitions and sorted 360 held-out questions (30 per cluster, cluster letters shuffled); "recall" is the share of a cluster's held-out questions it placed back in that cluster. The contrast compares each cluster with its nearest centre.

Agreement between the four readings

Pairs of readings compared on the same cluster. Same L2: both readings' parent skills match (chance ≈ 1 in 26). L3 overlap: shared sub-skills between the two top-5 lists (chance ≈ 0.07). Judge: a blind model call that saw readings 1, 2 and 4 unlabelled, in shuffled order, and rated each pair same / overlapping / different main skill. The hierarchy is a statement about pairs, so it is read through each cluster's nearest centre: does that neighbour have the same characteristic parent skill?

    The judge is lenient: it rated 1 of 72 pairs "different". Its one-line skill summaries were checked by hand on all 24 clusters.

    Method and cost

    Clusters: tree_cluster_k12.py, K = 12 over 63,610 text items; skill encoder t2_w0_lam0_x15/epoch_10, frozen gte-modernbert-base; node embeddings computed on CPU the way the trainer embeds (CLS pooling, L2 norm; 64 re-embedded questions match the stored vectors at cosine ≥ 0.9995). Language-model calls: claude-sonnet-5-5 through the Claude Code CLI, thinking off (0 thinking tokens), no tools; token log-probabilities are not available on that route. 84 calls in all (60 names / contrasts / checks + 24 judge), $4.07 at API list price, $0 billed (subscription).
