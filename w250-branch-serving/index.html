Serving a branching LLM-agent simulation: 251 counterfactual branches on 4 × A100

Baseline run for a systems study of intervention-aware LLM serving. Branches run one at a time per GPU, with the prefix cache flushed before each. Run of 2026-11-25 (Slurm job 63508559).

Setup

  • Workload. An OASIS social-media simulation with 250 LLM agents (36 well-connected "core" users). After a warm-up, the world is forked at step 6: a control branch, plus one branch per agent in which that agent posts the same rumour. Each branch then runs steps 7–16. Agents are activated by a seeded draw, so the same agents act at the same step in every branch. Only the content they see differs.
  • Model and server. Qwen3-4B-Instruct-2507 on SGLang 0.5.10.post1 with deterministic inference (Triton attention), the lpm schedule, chunked prefill of 4,096 tokens, and HiCache (host KV tier at 1.5× the GPU pool, write-through, LRU). The GPU KV pool holds 431k tokens. Every call returns top-5 logprobs.
  • Hardware. One whole node, held exclusively: 4 × A100-SXM4-80GB (NVLink), 2 × 32-core Ice Lake, 1 TB RAM. One server per GPU. Each server runs about 63 branches in sequence, with its client's cores and memory bound to that GPU's NUMA node. All 36 nodes of the partition are this type.
  • Comparison run. The MIG comparison (figure 3) uses an earlier test on one MIG 3g.20gb slice of an A100, with the same server settings and the same four branches.

Caveats

  • Extra GPU and node telemetry (DCGM counters, 1-s PCIe, per-core CPU) was attached 2.1 h into the 5.7 h job, so figures 6 and 7 cover only the last 3.6 h. That monitor ran as one extra process on core 0. Branches took 327.7 s on average before it attached (93 branches) and 325.5 s after (155 branches).
  • The MIG and A100 runs are separate jobs on different nodes, though they use the same code, server flags and branches.
  • Cross-branch reuse is measured offline, as the longest common token prefix with other branches' prompts for the same agent and step. It is an upper bound on what running branches together could reuse, not a measured speed-up.
  • 286 of 82,827 requests (0.35%) ended in an abort. 248 of these are one call, agent 147 at step 7, which aborted in 248 of the 251 branches. So the aborts are a property of that prompt, not of load.
  • The concurrent counterpart of this run, which would test cross-branch reuse directly, has not been run yet.
