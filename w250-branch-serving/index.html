Serving a branching LLM-agent simulation: 251 counterfactual branches on 4 × A100

Two parts: serving results and what the simulation found (which seeder spread the rumour fastest).

Baseline run for a systems study of intervention-aware LLM serving. Branches run one at a time per GPU, with the prefix cache flushed before each. Run of 2026-11-25 (Slurm job 63508559).

Setup

  • Workload. An OASIS social-media simulation with 250 LLM agents (36 well-connected "core" users). After a warm-up, the world is forked at step 6: a control branch, plus one branch per agent in which that agent posts the same rumour. Each branch then runs steps 7–16. Agents are activated by a seeded draw, so the same agents act at the same step in every branch. Only the content they see differs.
  • Model and server. Qwen3-4B-Instruct-2507 on SGLang 0.5.10.post1 with deterministic inference (Triton attention), the lpm schedule, chunked prefill of 4,096 tokens, and HiCache (host KV tier at 1.5× the GPU pool, write-through, LRU). The GPU KV pool holds 431k tokens. Every call returns top-5 logprobs.
  • Hardware. One whole node, held exclusively: 4 × A100-SXM4-80GB (NVLink), 2 × 32-core Ice Lake, 1 TB RAM. One server per GPU. Each server runs about 63 branches in sequence, with its client's cores and memory bound to that GPU's NUMA node. All 36 nodes of the partition are this type.
  • Comparison run. The MIG comparison (figure 3) uses an earlier test on one MIG 3g.20gb slice of an A100, with the same server settings and the same four branches.

What the run found: which seeder spread the rumour fastest

Each of the 250 seeded branches starts from the same world at step 6. One agent posts the same water-contamination rumour; the branches then run steps 7–16. Exposure counts agents whose feed showed the seed post or a repost or quote of it. Engagement counts agents who liked, commented on, reposted or quoted it, or followed the seeder.

  • Every seeded rumour spread, but slowly. By step 16 the median branch reached 12.8% of the 250 agents and the widest 29.6%. 186 branches passed 10%, and only 2 passed 25%. Growth is close to linear rather than a cascade. Reposts are few (a median of 1 per branch), but the first one matters a lot (R3).
  • Fastest: agent 18, a core user with 36 followers. Its rumour reached 74 agents (29.6%), with 37 engaging and 9 reposts or quotes; 10% by step 10, 25% by step 15. Next: agent 23 (70) and agent 34 (62). The top 20 are all core users.
  • Core users spread it further. Median reach 20.2% when one of the 36 core users posts it vs 12.4% for a regular user (engagement 8.0% vs 3.2%). Among core users, follower count predicts reach only weakly (Spearman 0.45).
  • One repost by core user 22 at step 7 decides most outcomes. It happened in 179 of 250 branches. Regular seeders split into two tight groups: 5.2% reach without that repost (64 branches) and 12.8% with it (150 branches). For regular seeders this is not about the seeder. The post has the same id in every regular branch, and the recommender shows it to the same two agents at step 7 (22 and 199). Agent 22's prompt differs between branches only in the author's id number, and its sampling seed is the same. It always comments, and reposts in 150 of 214 branches. The two outcome groups are one sampled decision flipping on that number.
  • Why regular users have no followers. The follow graph copies the OASIS paper's misinformation setup (App. E.2): regular users follow the core users who share an interest topic, and the paper describes no other follows. We read that as none, so the 214 regular users have no followers and the 36 core users hold all 1,073 follow edges. A regular user's post reaches others only through the recommender's random slots, comments, or a core user's repost. So the core vs regular gap is partly built into the graph, and a less arbitrary graph is planned.
  • Engagement is mostly comments. Summed over branches: 1,873 agents commented, 471 liked and 315 reposted. 1,903 posts and comments mention the rumour's keywords.

Limits: the follow graph above. One run per seeder. Sampling uses temperature 0.7 with seeds fixed per call, and agents are activated by a seeded draw that is the same in every branch. So differences of a few agents between core seeders may not hold up across repeats. The model is Qwen3-4B, not the OASIS paper's Llama-3-8B, and the world is a 250-agent scaled-down version of the paper's.

Caveats (serving results)

  • Extra GPU and node telemetry (DCGM counters, 1-s PCIe, per-core CPU) was attached 2.1 h into the 5.7 h job, so figures 6 and 7 cover only the last 3.6 h. That monitor ran as one extra process on core 0. Branches took 327.7 s on average before it attached (93 branches) and 325.5 s after (155 branches).
  • The MIG and A100 runs are separate jobs on different nodes, though they use the same code, server flags and branches.
  • Cross-branch reuse is measured offline, as the longest common token prefix with other branches' prompts for the same agent and step. It is an upper bound on what running branches together could reuse, not a measured speed-up.
  • 286 of 82,827 requests (0.35%) ended in an abort. 248 of these are one call, agent 147 at step 7, which aborted in 248 of the 251 branches. So the aborts are a property of that prompt, not of load.
  • The concurrent counterpart of this run, which would test cross-branch reuse directly, has not been run yet.
